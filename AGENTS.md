# AGENTS.md - ForceSampleDelay Development Guide

## Project Overview

**ForceSampleDelay** is a JUCE-based audio plugin that introduces adjustable delay (plugin delay compensation) into the DAW effect chain for lookahead simulation. It provides a pass-through signal with controlled latency to manually match delays between different tracks without relying on DAW's automatic delay compensation.

**Tech Stack:**
- JUCE Framework (audio plugin framework)
- C++20
- CMake build system
- Formats: VST3, Standalone

---

## Build Commands

### Initial Setup
```bash
# Clone with submodules (JUCE is in externals/)
git clone --recursive <repo-url>

# If already cloned without submodules:
git submodule update --init --recursive
```

### Build (CMake)
```bash
# Configure
cmake -B build -DCMAKE_BUILD_TYPE=Debug

# Build all targets
cmake --build build --config Debug

# Build specific target
cmake --build build --config Debug --target ForcePDC_VST3
cmake --build build --config Debug --target ForcePDC_Standalone
```

### Windows-specific (with Visual Studio)
```bash
# Use cmake-build-debug directory (CLion convention)
cmake -B cmake-build-debug -G "Visual Studio 17 2022" -A x64
cmake --build cmake-build-debug --config Debug
```

### Testing
This project does not currently have automated tests. Testing is done by:
1. Building the plugin
2. Loading in a DAW (Reaper, Ableton, etc.)
3. Verifying delay behavior with test signals

## Code Style Guidelines

### General Principles
This codebase follows **JUCE conventions** and modern C++ practices.

### Naming Conventions

**Classes:**
- PascalCase for classes: `ForceSampleDelayPluginAudioProcessor`, `ForceSampleDelayPluginAudioProcessorEditor`
- JUCE naming pattern: `<ProjectName>AudioProcessor`, `<ProjectName>AudioProcessorEditor`

**Variables:**
- camelCase for local variables: `currentSampleRate`, `writePos`, `delayBufferSize`
- camelCase for member variables: `delayBuffer`, `currentLatencySamples`
- No prefix conventions (no `m_`, `_`, etc.)

**Functions:**
- camelCase for methods: `prepareToPlay`, `processBlock`, `updateLatencyFromParam`
- JUCE overrides match framework naming exactly

**Constants:**
- SCREAMING_SNAKE_CASE for macros: `JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR`

### Formatting

**Indentation:**
- 4 spaces (no tabs)
- Consistent throughout codebase

**Braces:**
- Opening brace on same line for functions, classes, control structures
```cpp
void functionName()
{
    if (condition)
    {
        // code
    }
}
```

**Spacing:**
- Space after keywords: `if (condition)`, `for (int i = 0; ...)`
- No space between function name and parentheses: `functionName()`
- Space around operators: `a = b + c`, `x == y`

**Line Length:**
- No strict limit, but keep reasonable (~120 chars)
- Break long parameter lists across lines with proper indentation

### Headers and Includes

**Include Order:**
1. Own header first (in .cpp files)
2. JUCE headers: `<JuceHeader.h>` (auto-generated by JUCE build)
3. Standard library (if needed)
4. Local project headers

**Include Guards:**
- Use `#pragma once` (already standard in codebase)

**Example:**
```cpp
#include "PluginProcessor.h"
#include "PluginEditor.h"
```

### Types

**Prefer JUCE types for audio/GUI:**
- `juce::AudioBuffer<float>` for audio buffers
- `juce::AudioProcessor` base class
- `juce::String` for strings
- `juce::Slider`, `juce::Label` for GUI components

**Use standard C++ types elsewhere:**
- `int`, `float`, `double` for primitives
- `std::vector`, `std::unique_ptr` for containers/smart pointers

**Initialization:**
- Use brace initialization where clear: `int delayBufferSize = 0;`
- Use constructor initialization lists for member variables

### Function Patterns

**Override specifiers:**
- Always use `override` keyword for virtual function overrides
- Use `= default` for default implementations: `~Class() override = default;`
- Use `= delete` for disabled functions (copy constructors)

**Const correctness:**
- Mark methods `const` when they don't modify state
- Use `const` references for parameters: `const BusesLayout& layouts`
- Prefer `const` over `#define`

**Parameter passing:**
- Pass primitives by value: `void setDelay(int samples)`
- Pass objects by const reference: `void processBlock(juce::AudioBuffer<float>& buffer, juce::MidiBuffer& midi)`
- Use pointers for optional/nullable: `auto* p = apvts.getRawParameterValue("lookaheadMs")`

### Error Handling

**Assertions:**
- Use `jassert()` for debug-time checks (JUCE macro)
- Use `juce::jmax()`, `juce::jmin()` for bounds safety

**Validation:**
- Check for valid state in `prepareToPlay`, `processBlock`
- Validate bus layouts in `isBusesLayoutSupported`
- Guard against division by zero, negative values

**No exceptions:**
- Audio code should be exception-free (realtime constraint)
- Handle errors gracefully with early returns or default values

**Example:**
```cpp
if (currentLatencySamples == 0)
    return; // pass-through

const int needed = juce::jmax(1, currentLatencySamples + 1); // avoid zero
```

### Comments

**When to comment:**
- Complex DSP logic (delay buffer management, pointer wrapping)
- Non-obvious design decisions
- Parameter ranges and their reasoning

**Style:**
- Use `//` for single-line comments
- Use `/* ... */` for multi-line explanations
- Prefer self-documenting code over excessive comments

**Example:**
```cpp
// Tell the host our latency so it can compensate (PDC).
setLatencySamples(currentLatencySamples);

// Read position is writePos - latency (wrapped).
int readPos = localWritePos - currentLatencySamples;
if (readPos < 0)
    readPos += delayBufferSize;
```

## JUCE-Specific Patterns

### Plugin Structure
- Processor class inherits from `juce::AudioProcessor`
- Editor class inherits from `juce::AudioProcessorEditor`
- Use `JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR` macro for both

### Parameter Management
- Use `juce::AudioProcessorValueTreeState` (APVTS) for parameters
- Create parameters in `createParameterLayout()` static method
- Use `juce::ParameterID` with version number
- Attach UI controls via `SliderAttachment`, `ButtonAttachment`, etc.

### Audio Processing
- Initialize resources in `prepareToPlay()`
- Clean up in `releaseResources()`
- Process audio in `processBlock()`
- Call `setLatencySamples()` to report delay compensation to host

### State Management
- Serialize state in `getStateInformation()`
- Deserialize in `setStateInformation()`
- Use `ValueTree::readFromData()` and `writeToStream()`

## Common Gotchas

1. **Delay buffer wrapping:** Always modulo by `delayBufferSize` to wrap pointers
2. **Thread safety:** `processBlock()` runs on audio thread - no allocations, no locks
3. **Latency updates:** Safe to call `setLatencySamples()` during `processBlock()` in JUCE
4. **Channel count changes:** Always validate `BusesLayout` in `isBusesLayoutSupported()`
5. **JUCE submodule:** Must use `git submodule update --init --recursive` on fresh clone

## Development Workflow

1. **Making changes:**
   - Edit source files in `src/`
   - Rebuild: `cmake --build cmake-build-debug --config Debug`
   - Test in DAW

2. **Adding parameters:**
   - Add to `createParameterLayout()` in `PluginProcessor.cpp`
   - Add UI control + attachment in `PluginEditor.cpp`
   - Update `getStateInformation/setStateInformation` if needed

3. **Debugging:**
   - Use `DBG()` macro for console output (JUCE)
   - Attach debugger to DAW process
   - Check `cmake-build-debug/` for logs

4. **Clean build:**
   ```bash
   rm -rf cmake-build-debug
   cmake -B cmake-build-debug
   cmake --build cmake-build-debug --config Debug
   ```
